There are currently several major problems with this repository. 

- The steering module in @steering/voxposer_steering.py is incredibly bloated. We are trying to accomplish two different types of steering. We want to steer in trajectory space so that the end-effector falls into the right affordance basin (the lowest cost region of the value maps) and also avoid high penalty regions in the map that are imposed by the avoidance maps. The second steering is on rotational predictions so that we can communicate 'rotate left' and 'rotate right' or 'rotate upwards' or 'rotate downwards.' Now, it is important that these are not hardcoded objectives or hacked into the steering method. A value map will be imposed on the rotational targets (in quaternions or matrices so that we avoid the monkey latch problem), and we need to pass gradients to the predicted rotations to steer predictions into a certain mode of execution. This steering module should not have any 'gates' or 'hacks' that are necessary to allow for multiple stages of steering. These should live somewhere else. We should retain the ability to do adaptive guidance although the code for this can be incorporated in a cleaner way (both for rotations and for trajectory guidance). Please survey the repository to plan a separation for these various components.
